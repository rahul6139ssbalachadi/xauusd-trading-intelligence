1. SYSTEM ARCHITECTURE
================================================================================

Directory structure:
  market_data/    — MT5Provider (read-only, demo-guarded), CSVProvider, SQLite storage
  indicators/     — EMA, SMA, RSI (Wilder), ATR (Wilder), ADX (+DI/-DI), Bollinger Bands
  market_structure/ — Swing highs/lows, HH/HL/LH/LL, BOS/CHoCH, sessions, volatility regime
  strategy/       — Strategy dataclass (versioned, JSON-serializable), evaluate() -> BUY/SELL/WAIT
  backtest/       — Event-driven backtest engine (intrabar SL/TP, spread+slippage+commission)
  validation/     — Train/val/test split (60/20/20), walk-forward windows, IS/OOS degradation
  risk/           — Fixed-fractional sizing, hard guards (max_positions, risk caps)
  paper/          — Simulation-only journal (JournalStore JSONL), paper_run() decision logger
  reporting/      — ExperimentRegistry (EXP-/STRAT-/BACKTEST-/PAPER- IDs), text/HTML reports
  montecarlo/     — Shuffle/scatter/jitter robustness, ruin probability, is_robust flag
  candles/        — Candle-pattern stats (doji, hammer, engulfing, inside bar, pin bar)
  research/       — Standalone research scripts (V1-V10 grid search harnesses + probes)
  rk_trade/       — Multi-user live analysis platform (analysis-only, no execution)
  runner/         — CLI command runner (/market, /analyze, /signal, /backtest, etc.)
  db/             — SQLite database (db/trading.db)
  config/         — settings.toml, mt5.toml, symbols.toml, risk_limits.toml
  scripts/        — analyze_gold.py, ingest_gold_scalp.py, probe_mt5.py, etc.
  tests/          — 176 pytest tests (unit + integration + real-data smoke)
